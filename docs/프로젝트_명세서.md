## 1. Java Project

### 1.1 목표

- 식단정보를 기반으로 **Java 콘솔 애플리케이션**을 설계/구현한다.
- 객체지향 개념(**캡슐화 / 상속 / 다형성**)을 실제 프로젝트 구조에 적용한다.
- **Collection Framework(List/Map)** 와 **File I/O** 를 활용하여 **CRUD 기반 데이터 관리**를 구현한다.
- 구조화된 데이터 형식(**JSON/XML/CSV** 등)을 이해하고, 라이브러리로 **직렬화/역직렬화**를 수행한다.
- **요구사항 정의 → 설계 → 구현 → 검증**의 개발 전 과정을 경험한다.
- **생성형 AI** 를 설계 보조 및 기능 확장 도구로 활용한다.

### 1.2 준비사항

#### 1) 프로젝트 구조

콘솔 애플리케이션에 적합한 단순 구조로 구현하되, 유지보수를 위해 역할을 분리한다.

| 계층 | 역할 |
|------|------|
| **UI (Menu)** | 콘솔 메뉴 출력 및 사용자 입력 처리 · 입력값 검증(형식/빈값 등) 후 Manager 호출 · 처리 결과 메시지를 콘솔에 출력 |
| **Manager (업무/도메인 처리)** | 회원 관리, 식단정보 CRUD 등 핵심 기능 로직 처리 · 데이터의 생성/수정/삭제 시 필요한 규칙 수행 |
| **Repository (저장소)** | 메모리 저장(Collection: List/Map) 담당 · 파일(JSON) 저장/로드 제공 · 프로그램 시작 시 로드, 종료/변경 시 저장 |
| **Domain** | User 및 식단정보 클래스 정의 · DTO 필요 시 Domain 또는 별도 `dto` 패키지에 정의 |
| **Util** | 파일 입출력 · JSON 파싱 · 공통 유틸 기능 |

#### 2) 사용 데이터

- 음식 DB (CSV 데이터 제공)
- 2023 국민건강 통계 데이터 (XLSX 데이터 제공)
- 회원 데이터 — 회원 정보 JSON 파일 (필요시 직접 작성)

> ※ 데이터 저장 방식은 DB 가 아닌 **파일 기반 저장(File I/O)** 을 기본으로 한다.

#### 3) 개발언어 및 툴

- **Java 17+**
- **STS (Spring Tool Suite)**
- 콘솔 기반 실행 환경

#### 4) 필수 라이브러리 / 오픈소스

- **GSON 또는 Jackson** (JSON 파싱 및 직렬화)

### 1.3 작업 순서

1. 제공받은 음식DB 정보 구조를 확인하여 식단 정보를 설계한다.
2. 프로젝트의 핵심 기능과 범위를 정의한다.
3. 회원과 식단의 핵심 엔티티를 도출한다.
4. 필수/추가/심화 기능을 구분하여 요구사항을 작성한다.
5. 저장해야 하는 데이터 목록을 정리하고 엔티티 정의표를 작성한다.
6. 엔티티 정의표를 바탕으로 도메인 클래스(User, DomainEntity 등)를 설계한다.
7. UI(Menu), Manager, Repository 역할을 구분하여 클래스 다이어그램을 작성한다.
8. 생성형 AI 를 활용하여 클래스 다이어그램을 검토하고 개선한다.
9. Java 콘솔 프로젝트를 생성하고 패키지 구조를 설계한다.
10. 기본 기능을 구현한다.
11. 추가 기능을 구현한다.
12. 심화 기능(생성형 AI 활용 기능/아이디어)을 구현(작성)한다.
13. 프로젝트를 테스트하고 결과물을 제출한다.

### 1.4 요구사항

본 프로젝트는 식단 분석을 활용한 개인 맞춤형 건강 코칭 서비스(이하 **"냠냠코치"**)를 구현한다. 식품의약품안전처가 제공한 음식별 영양성분 데이터를 활용하여, 작성한 식단을 사용자가 원하는 목표(운동, 질병 등)에 따라 분석하여 정보를 제공한다. 또한 건강 목표를 위한 챌린지, 식단 리뷰 및 정보 교류 커뮤니티 등 다양한 기능을 제공하는 Java 콘솔 기반 관리 시스템을 구현한다.

### 요구사항 상세

#### 1. 기본 기능 (필수)

**식단 정보 관리 기능**

- **F101** — 식단 정보 데이터를 입력하여 새로운 기록을 생성할 수 있어야 한다. 사용자는 콘솔 메뉴를 통해 데이터를 입력할 수 있어야 한다.
- **F102** — 저장된 식단 정보 데이터를 조회할 수 있어야 한다. 전체 목록 조회로 모든 데이터를 확인할 수 있어야 하며, 각 데이터는 식별 가능한 **ID** 기준으로 구분되고 해당 ID로 단일 상세 조회가 가능해야 한다.
- **F103** — 기존 식단 정보 데이터를 수정할 수 있어야 한다. 수정할 데이터의 **ID**를 선택하여 수정한다.
- **F104** — 기존 식단 정보 데이터를 삭제할 수 있어야 한다. 삭제할 데이터의 **ID**를 선택하여 삭제한다.
- **F105** — 사용자는 입력한 식단 기록을 분석하여 영양 정보를 표현(점수 등)할 수 있어야 한다.

**회원 관리 기능** *(← 사용자 담당)*

- **F106** — 회원 가입으로 사용자 정보를 등록. 아이디, 비밀번호, 이름 등의 정보를 입력하여 회원가입을 수행.
- **F107** — 회원 정보 조회. 로그인한 사용자는 자신의 회원 정보를 조회할 수 있어야 한다.
- **F108** — 회원 정보 수정. 사용자는 본인의 회원 정보를 수정할 수 있어야 한다.
- **F109** — 회원 정보를 삭제하거나 비활성화. 회원 탈퇴 기능으로 서비스 이용을 종료할 수 있어야 한다.
- **F110** — 로그인/로그아웃 제공. 아이디·비밀번호로 로그인하며, **로그인 상태에 따라 접근 가능한 메뉴가 달라져야 한다.**

#### 2. 추가 기능

- **1) 회원 정보 추가 기능**
  - **F111** — 다른 사용자를 팔로우/팔로잉 할 수 있어야 한다. 등록, 조회, 삭제 기능 구현.
- **2) 챌린지 기능**
  - **F112** — 챌린지 정보(기간, 설명, 이미지 등)를 등록/조회/삭제.
  - **F113** — 사용자는 챌린지를 참여하고, 달성도 등 정보를 수정·관리.
- **3) 커뮤니티 기능** *(← 파트너 담당)*
  - **F114** — 식단 리뷰/전문가/자유 게시판 등을 설계하고, 각 게시판은 글 등록·조회·수정·삭제 가능.
  - **F115** — 게시글에 대한 댓글을 작성·조회·수정·삭제 가능.

#### 3. 심화 기능

생성형 AI를 활용하여 식단 데이터 또는 시스템 사용 경험을 확장하는 기능을 아이디어 작성 또는 구현한다.

- **F116** — 생성형 AI를 활용한 식단 분석 기능 구현.
- **F117** — 생성형 AI를 활용한 운동 코칭 기능 구현.

### 데이터 구조 참고

**식단 (`diet-data.json`)** — `meals[]` 각 항목:
```
id, date, type(아침/점심/저녁), foods[]{ name, calories, protein, carbs, fat }
```
- `nutritionGoals`: `{ dailyCalories, protein, carbs, fat }`
- `weeklyStats`: `{ startDate, endDate, total*, average* }`

**챌린지 (`challenges.json`)** — `challenges[]` 각 항목:
```
id, title, description, type(protein/calories/carbs/fat/meals),
goal, current, startDate, endDate, status(active), participants
```

**커뮤니티 (`community.json`)** — `posts[]` 각 항목:
```
id, title, content, author, date, category(질문/정보/식단),
likes, comments[]{ id, author, content, date }
```
